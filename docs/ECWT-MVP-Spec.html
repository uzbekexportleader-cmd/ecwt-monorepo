MVP spetsifikatsiyasi — v1

ECWT — O'zbekiston elektron tijorat kompaniyasi

O'zbekistonlik tadbirkor, ishlab chiqaruvchi va hunarmandlarni xalqaro marketplace'larga chiqaruvchi B2B xizmat platformasi. Ushbu hujjat investor oldida to'liq ishlaydigan MVP uchun ekranlar, oqimlar, ma'lumotlar modeli va qurish tartibini belgilaydi.

Sana: 2026-08-16 Holat: qurish boshlanishidan oldingi tasdiq kutilmoqda Stack: Next.js · Expo · NestJS · PostgreSQL

Uchta qoida butun hujjat bo'ylab amal qiladi.

1 — Subsidiya ariza jarayoni, kafolat emas. UI hech qayerda subsidiyani avtomatik beriladigan narsa sifatida ko'rsatmaydi.

2 — Marketplace statuslari MVP'da qo'lda boshqariladi. Bu investorga aytiladi, yashirilmaydi.

3 — Analitika raqamlari MVP'da demo ma'lumot. Ular bazada source = DEMO bilan ajratiladi va UI'da belgilanadi.

16Investor demo — click-by-click, 4 daqiqa

Ikkita brauzer oynasi oldindan ochiq bo'ladi: birinchisida tadbirkor akkaunti, ikkinchisida ECWT admin paneli. Telefon ham tayyor turadi.

  1. 0:00–0:20 Landing sahifa ochiladi. "Mahsulotingizni dunyoga olib chiqing" — bitta jumla bilan biznes tushuntiriladi. Ro'yxatdan o'tish bosiladi.
  2. 0:20–0:50 Ro'yxatdan o'tish formasi to'ldiriladi. Onboardingning birinchi ikki qadami ko'rsatiladi, qolgani oldindan to'ldirilgan akkauntga o'tiladi (vaqtni tejash uchun).
  3. 0:50–1:20 Dashboard. Aktiv mahsulotlar, xizmatlar va listing holati ko'rinadi. + Mahsulot qo'shish bosiladi.
  4. 1:20–1:50 Mahsulot formasi to'ldiriladi (nomi, kategoriya, narx, rasm) va Tekshiruvga yuborish bosiladi. Holat SUBMITTED ga o'zgaradi.
  5. 1:50–2:10 "Xizmat haqini qanday to'laysiz?" ekrani. Bu — demoning markazi. Subsidiya orqali tanlanadi, ariza yuboriladi. Ekranda "bu ariza, kafolat emas" yozuvi ko'rsatiladi.
  6. 2:10–2:50 Admin oynasiga o'tiladi. Dashboardda yangi mahsulot va yangi subsidiya arizasi ko'rinadi. Mahsulot ochiladi va Approve bosiladi. Subsidiya arizasi ochiladi, hujjatlar ko'riladi, Approved → Funded qilinadi.
  7. 2:50–3:20 Admin panelda marketplace operatsiyalari ochiladi. Amazon ustuni: PREPARING → READY → SUBMITTED → LIVE. Tashqi havola kiritiladi. Bu qadamda aniq aytiladi: "Bu operatsiyani hozir bizning menejerimiz bajaradi. API integratsiyasi keyingi bosqichda."
  8. 3:20–3:45 Tadbirkor oynasiga qaytiladi va sahifa yangilanadi: mahsulot APPROVED, Amazon LIVE, bildirishnomalar kelgan, dashboardda analitika ko'rinadi. Analitika yonidagi "demo ma'lumot" belgisi ko'rsatiladi va izohlanadi.
  9. 3:45–4:00 Telefon ko'tariladi. Mobil ilovada xuddi shu holat: mahsulot LIVE, bildirishnoma kelgan. Bitta backend, uchta klient.

Demo qoidasi. Hech bir qadamda soxta ma'lumot ko'rsatilmaydi. Qo'lda bajariladigan joy aytiladi, demo analitika belgilanadi. Investor keyinroq buni o'zi topib olsa — ishonch yo'qoladi; oldindan aytilsa — jamoaning ishonchliligi ko'rinadi.

20Stack qarorlari

ORM — Prisma

Ikkalasi ham ishlaydi, lekin bu loyihada Prisma aniq afzal:

  • Bitta sxema fayli — bitta haqiqat manbai. 24 ta entity va ular orasidagi bog'lanishlarni bitta faylda ko'rish mumkin. TypeORM'da model dekoratorlarga tarqalib ketadi va vaqt o'tib bazadagi holat bilan mos kelmay qoladi.
  • Generatsiya qilingan tiplar. include va select natijasi ham to'liq tiplashadi. TypeORM'da bu joyda ko'p any paydo bo'ladi.
  • Migratsiyalar ishonchli. migrate dev va migrate deploy ajratilgan, tarix fayl sifatida saqlanadi.
  • Kamchiligi: juda murakkab SQL so'rovlar uchun qulay emas. Bu holda $queryRaw ishlatiladi — MVP uchun analitika agregatlarida bir-ikki joyda kerak bo'ladi, xolos.

Auth — email + parol, JWT + rotating refresh token

MVP uchun eng sodda xavfsiz variant:

  • Parol argon2id bilan xeshlanadi (OWASP tavsiyasi).
  • Access token — JWT, 15 daqiqa. Har so'rovda bazaga murojaat qilinmaydi.
  • Refresh token — 48 baytli tasodifiy satr, bazada faqat SHA-256 xeshi saqlanadi, ishlatilganda almashtiriladi (rotation). Bekor qilingan token qayta ishlatilsa — o'g'irlik belgisi, foydalanuvchining barcha sessiyalari yopiladi.
  • Websaytda tokenlar httpOnly cookieda, mobil ilovada Keychain / Keystoreda (expo-secure-store). Brauzer JavaScript'i tokenni ko'rmaydi.
  • Brute-force himoyasi: 5 marta xato kirishdan keyin 15 daqiqa blok + IP bo'yicha rate limit.
  • Nega OAuth emas: maqsadli auditoriya — O'zbekiston tadbirkorlari, ularda korporativ Google/Apple akkaunt kam. Telefon OTP kelajakda qo'shiladi (Eskiz.uz), lekin u SMS provayder shartnomasiga bog'liq va MVP'ni to'xtatib turmasligi kerak.

Fayllar — drayver abstraksiyasi

StorageService interfeysi, ikkita amalga oshirish: lokal disk (dev va demo) va S3-mos (Cloudflare R2 yoki AWS). Yuklash presigned URL orqali — fayl backend orqali o'tmaydi.

Nima qilinmaydi

Microservice yo'q, Kubernetes yo'q, realtime WebSocket yo'q, AI funksiya yo'q, murakkab analytics pipeline yo'q. Bitta NestJS monolit, bitta PostgreSQL. Biznes oqimi ishlagandan keyin kengaytiriladi.

BUILD START CHECKPOINTQurishni boshlashdan oldin

Kod yozilmaydi. Quyidagilarni tasdiqlashingiz yoki o'zgartirishingiz kerak:

  • Ekranlar ro'yxati — 90 ta ekran. Ortiqchasi bormi, yetishmayotgani bormi?
  • Subsidiya oqimi — holatlar to'g'rimi? Real hayotda kim qaror qabul qiladi: ECWT o'zimi, yoki davlat organi/fondmi? Bu javob arxitekturaga ta'sir qiladi.
  • Xizmat narxlari — xizmat turlari va narxlari qanday? Foiz asosidami yoki qat'iy summami?
  • To'lov — MVP'ga Payme yoki Click shartnomasi ulguradimi, yoki bank o'tkazmasi + admin tasdiqlash bilan ketamizmi?
  • Marketplace — 4 ta platforma (Amazon, eBay, Walmart, Shopify) to'g'rimi? Sizda hozir qaysi ikkitasida akkaunt bor?
  • Rollar — ECWT_MANAGER va ADMIN ajratmasi kerakmi, yoki MVP'da bitta ADMIN yetarlimi?
  • Demo sanasi — investor uchrashuvi qachon? Fazalar shunga qarab qisqartiriladi.
  • Mavjud kod — oldingi sessiyada qurilgan backend (auth, mahsulot, to'lov modullari) bor. Uni shu yangi modelga moslab davom ettiramizmi, yoki noldan boshlaymizmi?

Siz tasdiqlamaguningizcha kod yozilmaydi.
